# S6.2 · Acceso al dossier desde el correo con un enlace de un solo uso

- **Tarea:** S6.2 · [tarjeta](https://trello.com/c/bRkzSIe3)
- **Responsable:** FD (traspasada de DG el 2026-11-10)
- **Brecha:** B5 · **Objetivo:** OE7
- **Depende de:** S6.1 (correo), S6.3 (correo de reunión), S6.4 (reintentos), S6.5 (retención)
- **Estado:** implementada · verificación en `specs/reports/S6.2-enlace-un-solo-uso.md`

## Problema

El botón del correo lleva al detalle del dossier en el dashboard, que exige iniciar sesión. Desde
el celular, o desde un equipo sin sesión, el usuario no puede abrirlo sin entrar con su cuenta.

## Decisión

Aprobada por FD el 2026-11-10:

- El enlace abre **solo ese dossier**, en una página de **solo lectura**, sin iniciar sesión. No da
  acceso al resto de la plataforma.
- Se gasta **al pulsar «Ver dossier»**, no al abrir la página: los filtros de los servidores de
  correo abren los enlaces solos para revisarlos y no deben gastarlo.
- **Vence en 24 horas**, como la retención.

## Diseño

### Token

- `secrets.token_urlsafe(32)` (256 bits). En la base se guarda solo su **SHA-256**.
- Va en el **fragmento** de la URL: `<frontend>/acceso#t=<token>`. El fragmento no viaja al
  servidor, así que no queda en los logs del frontend ni de los proxies.
- Tabla nueva `dossier_access_links`: `token_hash` (único), `dossier_id` (`ON DELETE CASCADE`),
  `user_id`, `organization_id`, `expires_at`, `used_at`, `created_at`.

### Canje

`POST /dossier-access` con `{"token": "…"}`, sin sesión:

- Un solo `UPDATE … SET used_at = now() WHERE token_hash = … AND used_at IS NULL AND
  expires_at > now() RETURNING dossier_id`: dos canjes a la vez nunca ganan los dos.
- **200** con `subject_name`, `body` (Markdown), `created_at` y `output_language`, solo si el
  dossier existe y está completo.
- **410** con un mensaje único para enlace inexistente, usado, vencido o dossier borrado: no se
  distingue el motivo.
- Límite por IP: `ACCESS_LINK_RATE_LIMIT` (20 por minuto) → 429.
- Cada canje deja `ACCESS dossier_link` en `audit_logs`, exitoso o fallido, sin el token.

### Correos

Los tres correos (Personas, reunión y el botón manual) crean un enlace por dossier al armarse:

- El botón (o cada nombre de la lista, en el de reunión) usa el enlace de un solo uso.
- Debajo, el enlace normal al dashboard y una nota: «El botón sirve una vez y vence en 24 horas».
- Si el envío falla, los enlaces creados se descartan con la transacción (y con un savepoint en
  los reintentos de S6.4).

### Frontend

Página pública `/acceso`: lee el token del fragmento, muestra «Ver dossier» y, al pulsarlo, canjea
y muestra el nombre y el informe (Markdown). Si el enlace ya no sirve, lo dice y ofrece iniciar
sesión. Textos en los 7 catálogos.

### Retención

`dossier_access_links` cae con el dossier (`ON DELETE CASCADE`) y entra en la verificación del
borrado de S6.5.

## Criterios de aceptación

| | Criterio |
|---|---|
| CA1 | Un enlace válido se canjea una vez y devuelve el dossier |
| CA2 | El segundo canje del mismo enlace responde 410 |
| CA3 | Un enlace vencido responde 410 |
| CA4 | Un enlace inexistente, de un dossier borrado o de uno no completo responde 410, con el mismo mensaje |
| CA5 | La base guarda solo el hash del token |
| CA6 | El enlace va en el fragmento de la URL del frontend |
| CA7 | Los tres correos llevan un enlace que funciona, el enlace al dashboard y la nota, en 6 idiomas |
| CA8 | Si el envío falla, no queda ningún enlace creado |
| CA9 | Cada canje queda auditado (`ACCESS dossier_link`), sin el token |
| CA10 | Más de 20 canjes por minuto desde una IP responden 429 |
| CA11 | Diez canjes simultáneos del mismo enlace: exactamente uno responde 200 |
| CA12 | La respuesta solo trae ese dossier, sin datos de la organización ni de otros dossiers |
| CA13 | La página `/acceso` no gasta el enlace hasta pulsar «Ver dossier», muestra el informe y explica cuando no sirve |
| CA14 | La migración crea la tabla y su `downgrade` la quita; el borrado por retención la incluye |
